## 指摘

### C1 🟡 お預りの上限が、注文の合計より低い

**場所**：`src/lib/domain/order.ts:4`（`TENDERED_MAX`）、`:92`（`parseTendered`）

**問題**：
- お預りの上限は 1,000,000円。一方、価格は最大 100,000円（`menu.ts` の `PRICE_MAX`）、1注文は50行・各99個までなので、合計は 1,000,000円を大きく超えうる
- 「ちょうど」は合計をそのまま入力欄に入れるが、`parseTendered` が上限を超える値を `null` にするため、「お預りは、0以上の整数で入れてください」と出る

**起こりうること**：100,000円の品を11個 → 合計 1,100,000円。「ちょうど」を押すとエラーになり、この注文は、お預りを入れられない（現金で確定できない）。

**直し方の案**（どちらか）：
- 上限を、ありうる合計の最大（`PRICE_MAX × QTY_MAX × ORDER_LINES_MAX`）以上にする
- 上限を「合計の何倍まで」のように、合計に合わせて決める（打ち間違いを防ぐ目的は保てる）

どちらにしても、screens.md §3.4 の「上限 1,000,000円」を合わせ、単体テストに、上限ちょうど・合計が 1,000,000円を超える場合を足す。

### C2 🟡 カートの ＋ で、売り切れ・削除された品を増やせる

**場所**：`src/lib/domain/order.ts:51`（`changeQty`）、`src/staff/order/OrderPage.tsx:136`（＋ ボタン）

**問題**：
- メニューのボタンは、売り切れの品を押せない（`addToCart` が `soldOut` を返す。ボタンも `disabled`）
- カートの ＋ は `changeQty` を呼ぶだけで、売り切れ・削除を見ていない
- screens.md §3.4 は、売り切れ・削除された行を「そのまま確定できる」としているが、数量を**増やせる**とは書いていない

**起こりうること**：カートに入れた後で、別の端末がその品を売り切れ（または削除）にする。行には「売り切れになりました」と出るが、＋ で数量を増やせて、無い品の注文が増える。

**直し方の案**：
- `lineNotice` の結果が `soldOut` または `deleted` の行は、＋ を `disabled` にする（−・削除は、そのまま使える）
- screens.md §3.4 に「売り切れ・削除された行は、減らす・消すだけできる」と書く

### C3 🟡 99個のときに ＋ を押しても、何も知らせない

**場所**：`src/lib/domain/order.ts:53`（`Math.min(QTY_MAX, …)`）

**問題**：
- ＋ は、99個を超えないよう、黙って止まる
- メニューのボタンから足したときは「1つの品は、99個までです」と出る（`OrderPage.tsx:41`）。screens.md §3.4 も「超えるときは、メニューの下に知らせる」としている

**起こりうること**：スタッフが ＋ を押しても数が変わらず、理由が分からない。

**直し方の案**（どちらか）：
- ＋ でも、上限に達したら同じ知らせを出す（`changeQty` が、上限に当たったことを返す。または、画面で `qty >= QTY_MAX` を見る）
- 99個のときは、＋ を `disabled` にする
