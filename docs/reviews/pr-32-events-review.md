## 指摘

### E1 🟠 保存したイベントIDが、サーバーの一覧に無くても、選んだままになる

**場所**：`src/staff/event/EventGate.tsx:18`

**問題**：`hei:currentEvent` にイベントIDが残っていると、ゲートは、そのまま中に入る。サーバーから届いた一覧（`fromCache: false`）に、そのイベントが無くても、選択を外さない。

**起こりうること**：
- オーナーがイベントを消した。または、自分がメンバーから外された
- ログアウトを通らずに、ログインが切れた（例：トークンが無効になった）。そのあと、別のアカウントで入ると、`logout()` が呼ばれないため、前の人のイベントIDが残る

**結果**：`currentEvent` が `undefined` のままになる。題名が「イベント」だけの、空の画面に入る。自分で「一覧へ」を押すまで、抜けられない。

**直し方の案**：サーバーの一覧が届いて、そこに保存したIDが無ければ、`selectEvent(null)` で選択を外す。

### E2 🟡 アカウントを切り替えた直後、前の人のイベント一覧が一瞬見える

**場所**：`src/state/myEvents.ts:19`

**問題**：ログアウトしても、`myEvents` と `subscribedUid` が消えない。

**結果**：別のアカウントでログインすると、`EventGate` の最初の描画で、前の人の `myEvents.value`（イベント名と日付）が、そのまま出る。消えるのは、`useEffect` の中の `subscribeMyEvents` が `null` にしたあと。

**直し方の案**：`logout()` か、サインアウトを検知したときに、一覧も消す。

### E3 🟡 一覧の購読が失敗すると、ページの再読み込みしか手がない

**場所**：`src/staff/event/EventListPage.tsx:54`

**問題**：
- コレクショングループの購読が失敗すると、Firestore は、その購読を止める
- ここで出る `ErrorView` には、やり直す手段がない。購読し直すのは、`onList` が変わったときだけで、一覧の画面からは変えられない。そのため、ページを再読み込みするまで、止まったままになる
- 一覧がすでにあるときに起きた失敗は、表示されない。そのため、古い一覧が、知らせなしに出続ける

**直し方の案**：`ErrorView` に「やり直す」を付けて、購読し直せるようにする。一覧があるときの失敗も、知らせる。
