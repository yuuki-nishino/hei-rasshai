## 指摘

### B1 🟡 `ポテト1,500` が「ポテト1」500円として通る

**場所**：`src/lib/domain/menu.ts:141`（`BULK_LINE`）

**問題**：
- 品名は最短一致（`.+?`）で、区切りにカンマを含む（`[\s,:]+`）。品名と価格の間に空白が無く、価格が3桁区切りのとき、3桁区切りのカンマが「区切り」と解釈される
- 実際の結果：`ポテト1,500` → `{ name: 'ポテト1', price: 500 }`（エラーにならない）
- data-model.md §5.6 は、`焼き 1,0,5` のような**不正な**カンマ区切りが通ることは認めている。しかし、`ポテト1,500` は、手で打つと自然に出る、**正しい**書き方の価格で、起こりやすさが違う

**起こりうること**：スタッフが、メモ帳に「ポテト1,500」「からあげ1,000」と書いて貼り付ける。プレビューには「ポテト1　500円」「からあげ1　0円（エラー）」と出る。後者はエラーで気づくが、前者は、品名の末尾の「1」と価格を見落とすと、500円で売られる（1,000円の売り漏れ）。

**直し方の案**（どちらか）：
- エラーにする：区切りが**カンマだけ**で、品名が数字で終わり、「品名の末尾の数字 ＋ `,` ＋ 価格」が3桁区切りの形（`\d{1,3}(,\d{3})+`）になる行は、「品名と価格の間に、空白を入れてください」のエラー行にする
- プレビューで目立たせる：上の条件の行に、注意の印（「品名の末尾の数字が、価格の一部かもしれません」）を付ける。追加は止めない

どちらにしても、data-model.md §5.6 の注記に、この例を足す。

### B2 🟡 `¥` の後の空白で、`¥` が品名に入る

**場所**：`src/lib/domain/menu.ts:141-142`（`BULK_LINE`・`PRICE_ONLY`）

**問題**：
- 正規表現は `¥?` の直後に数字を求める。`¥ 200` のように空白があると、`¥` が品名の側に入る
- 実際の結果：
  - `ラムネ ¥ 200` → `{ name: 'ラムネ ¥', price: 200 }`
  - `¥ 500` → `{ name: '¥', price: 500 }`（本来は「品名がありません」）
- 1件ずつの追加の `parsePrice` は、空白を除いてから見るため、`¥ 200` を受け付ける。同じ「価格」の書き方で、ふるまいが違う

**起こりうること**：表計算ソフトの通貨の表示や、手打ちで「￥ 300」と書いた品が、品名「かき氷 ¥」で登録される。プレビューで気づかなければ、お客様の画面・注文・CSV に、その品名のまま出る。

**直し方の案**：
- `¥` の後の空白を許す：`BULK_LINE` を `^(.+?)[\s,:]+(?:¥\s*)?(\d{1,3}(?:,\d{3})+|\d+)\s*円?$` に、`PRICE_ONLY` を `^(?:¥\s*)?(…)\s*円?$` にする（data-model.md §5.6 の正規表現も合わせる）
- 単体テストに `かき氷 ¥ 300`（通る）・`¥ 500`（品名がありません）を足す

### B3 🟡 正規化が、品名の中まで変える

**場所**：`src/lib/domain/menu.ts:130-137`（`normalizeBulkLine`）、`:152`・`:160`

**問題**：
- 正規化は行の全体にかかり、品名も、正規化した後の文字列から取り出している
- 実際の結果：
  - `たこ焼き（８個） 600` → 品名 `たこ焼き（8個）`（括弧は全角、数字は半角になる）
  - `Ａセット：大 500` → 品名 `Ａセット:大`
  - 品名の中の全角の空白も、半角になる
- 1件ずつの追加（`parseMenuName`）は、品名を変えない。同じ品名を、どちらで足したかで、表記が変わる
- 設計書（data-model.md §5.6）は「正規化して、価格と名前に分ける」としか書いておらず、品名が変わることは、決まっていない

**起こりうること**：利用者が全角で揃えて書いた品名が、半角まじりで登録される。お客様の画面・レシート代わりの表示で、表記が揃わない。

**直し方の案**：
- 正規化は、**分け方を決めるためだけ**に使い、品名は元の文から取り出す。`normalizeBulkLine` の置き換えは、どれも1文字 → 1文字（UTF-16 の1単位 → 1単位）で、長さが変わらないため、位置で切り出せる
  ```ts
  const t = raw.trim();
  const s = normalizeBulkLine(t); // 長さは t と同じ
  const m = BULK_LINE.exec(s);
  // …
  const name = parseMenuName(t.slice(0, m[1]!.length));
  ```
  （`　` は `trim()` でも空白として除かれるため、正規化の前に trim しても、結果は同じ）
- data-model.md §5.6 に「品名は、元の文のまま（正規化は、価格と区切りを見つけるためだけ）」と書く
- 単体テストに `たこ焼き（８個） 600` → 品名 `たこ焼き（８個）` を足す

### B7 🟡 品名の先頭の `-`・`*` が、箇条書きの記号として消える

**場所**：`src/lib/domain/menu.ts:92`（`BULLET = /^[-*•・]\s*/`）

**問題**：
- 記号の後ろの空白を `\s*`（0個でもよい）にしているため、品名の先頭の `-`・`*` も消える
- 実際の結果：
  - `-20%セット 800` → 品名「20%セット」
  - `*限定* 焼きそば 500` → 品名「限定* 焼きそば」（片方の `*` だけが消える）
- エラーにはならず、プレビューで品名を見比べないと気づかない（B3 で直した「品名が黙って変わる」と同じ種類の問題）

**直し方の案**：
- Markdown などの箇条書きは、`-`・`*`・`•` の後ろに空白がある。`・` は、空白なしで書くことが多い。そこで、`-`・`*`・`•` は空白が1つ以上あるときだけ除く
  ```ts
  const BULLET = /^(?:[-*•]\s+|・\s*)/;
  ```
- 単体テストに `-20%セット 800` → 品名「-20%セット」を足す。data-model.md §5.6 の「行頭の箇条書きの記号」に、「`-`・`*`・`•` は後ろに空白があるときだけ」と書く
