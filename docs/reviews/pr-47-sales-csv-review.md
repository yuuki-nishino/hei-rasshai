## 指摘

### S1 🟡 欠けた集計が、印なしで持ち出せる

**場所**：`src/staff/sales/SalesPage.tsx`（`copy()`、`saveCsv()`、`fromCache` の警告）

**問題**：
- `fromCache` が true のとき、画面には警告が出る。しかし、「集計をコピー」と「CSV保存」は、そのまま押せる
- コピーしたテキストと、保存した CSV には、「欠けているかもしれない」という印が無い

**起こりうること**：電波が弱い会場で、欠けた売上を LINE に貼る、または CSV を保管する。あとで見ると、正しいものに見える。

**直し方の案**：
- `fromCache` のあいだは、2つのボタンを無効にする。または、押したときに確認を出す
- 無効にしない場合は、テキストの1行目と、CSV のファイル名に、「（未確認）」を添える

### S2 ℹ️ iOS のホーム画面アプリで、CSV保存を確かめる

- Blob のダウンロード（`a.download`）は、iOS のスタンドアロン PWA で、ダウンロードにならず、プレビュー画面に遷移することがある。そこから戻れなくなる場合もある
- PR の本文でも、dev の実機確認は「これから」。Android と iPhone の両方で、押して保存できるかを確かめる
- うまくいかない場合は、集計のコピーと同じ形で、「選べる表示」に切り替える案がある

### S3 ℹ️ テストの無い境目と、運用

- `formatTime` は、`hourCycle: 'h23'` を指定している。0時台が「00:05:00」になることを確かめるテストが無い。深夜営業で、JST の 0 時をまたぐ注文を足すと、確かめられる
- CSV は1日分（data-model.md §5.5 に書かれている）。SPEC の「CSVの保存先」（C4）の運用として、イベント終了後に、日数分を保存する手間が出る。運用で決めておく

## 確かめて、問題が無かったこと

- **CSV の無害化**：先頭が `= + - @`・タブ・`\r` のセルに `'` を足し、全セルを `"` で囲み、中の `"` は `""` にする。品目・メモも対象で、数値も文字にして囲む。単体テストが、各先頭文字・改行入り・式のメモ・先頭が `-` の品名を確かめている
- **BOM・CRLF・列**：設計書の列（日付、番号、状態、支払い、合計、品目、メモ、作成、完成、渡し、取り消し）と一致する。取り消しも含む。時刻は JST
- **ファイル名**：`/ \ : * ? " < > |` と制御文字を `_` にし、空なら「イベント」にする
- **取得**：`fetchOrdersOfDay` は `getDocs` で、`fromCache` を返す。結合テストが、取り消しを含む順序・日付の絞り込み・0件・集計との組み合わせを、本物のルールの下で確かめている
- **画面**：
  - 日付を切り替えたときの古い結果は、`cancelled` で捨てる
  - 0件のときは、ボタンを出さない。取り消しだけの日は、0円で表示される
  - コピーの失敗時は、選べる表示に切り替わる。再取得で、その表示は消える
- **ルール**：変更なし。ルールのテストの追加は要らない
- **設計書・SPEC**：screens.md §3.6・§3.7、data-model.md §5.5、testing.md は、コードと合っている。SPEC 6.3 の要件（現金／PayPay／合計、メニュー別、コピー、CSV、取り消しを集計に入れない）を満たす
