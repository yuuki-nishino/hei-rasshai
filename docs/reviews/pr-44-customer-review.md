## 指摘

### V1 🟠 「通信が不安定です」が、オフラインで出ない

**場所**：`src/customer/CustomerApp.tsx:~40`（経過時間を数える `useEffect`）、`src/lib/domain/customerView.ts`（`customerView`）

**問題**：
- タイマーの副作用に、`if (snapshot) return;` がある。何か1つでも結果が届くと、タイマーが止まる。キャッシュ由来の結果（`order: null`、`fromCache: true`）も、これに当たる
- `customerView` は、この結果を `loading` にし、`slow` になるのは `waitedMs >= 8000` のとき。しかし、`waitedMs` は止まった時点の値（0〜1秒）のまま

**起こりうること**：電波が無い状態、または弱い状態で、QRのリンクを開く。最初に、キャッシュ由来の結果（文書なし）が届き、タイマーが止まる。「読み込み中…」だけが出続け、「通信が不安定です。電波の良い場所で、お待ちください」が出ない。screens.md §4.1 の設計（8秒続いたら slow）と食い違う。

**直し方の案**：
- タイマーは、「サーバーの結果が届く」か「注文が表示できる」まで止めない。たとえば、副作用の条件を `snapshot` の有無ではなく、`view.state === 'loading'` にする
- 画面のタイマーと判定の組み合わせを、偽のタイマーで確かめる（V4）

### V2 🟡 購読のエラーのあと、戻らない

**場所**：`src/lib/data/customerOrder.ts:~35`（`onSnapshot` のエラー処理）

**問題**：
- コメントは「通信できない（unavailable）など。購読は、SDK が再接続する」と書くが、これは誤り。一時的な圏外では、エラー処理は呼ばれず、SDK が再接続する。エラー処理が呼ばれるのは、**購読が終わる**とき
- エラーのあとは、`{ kind: 'error' }` で画面が「通信できません」になり、その後の状況の変化（「お待ち！」など）は、届かない

**起こりうること**：権限のエラーや、無料枠の上限（`resource-exhausted`）などで、購読が一度終わる。つながりが戻っても、お客様は、再読み込みするまで、「お待ち！」に気づけない。

**直し方の案**：
- エラーのあとは、間隔を空けて（バックオフ）購読し直す。または、「もう一度開いてください」の案内を、再読み込みのボタンつきにする
- コメントを、実際の動き（エラーは購読の終わり）に合わせて直す
- 表示中（`active`）のエラーでは、最後に届いた注文を残したまま、「通信できません」を添える形も検討する（いまは、カードが消える）

### V3 🟡 テストが、どちらの結果でも通る

**場所**：`test/data/customerOrder.test.ts`（`存在しない注文でも、キャッシュの結果（fromCache = true）の間は、notFound と判定しない`）

**問題**：
- 最初の結果が、キャッシュ由来なら `loading` を、そうでなければ `loading` か `notFound` のどちらでもよい、と確かめている。どちらの場合も通るため、何も守っていない
- 判定そのものは、単体テスト（`customerView.test.ts`）が確かめている。実害は小さい

**直し方の案**：テストを消す。または、購読を、ネットワークを切った状態で始め、最初の結果が `fromCache: true` で `loading` になることを、確実に確かめる。

### V4 ℹ️ 画面の組み合わせに、テストが無い

`customerView`（判定）と `CustomerApp`（タイマー・振動・題名）は、別々にしか確かめていない。V1 は、この境目の問題。V1 を直すときに、「経過時間を数える条件」を、純粋な関数に切り出すと、偽のタイマーで確かめられる。

## 確かめて、問題が無かったこと

- **お客様に渡す項目**：`toCustomerOrder` が、番号・状況・明細・合計だけに絞る。支払い方法・メモ・`createdBy` は、型にも持たない。結合テストが、キー集合と、`paypay`・メモ・uid を含まないことを確かめている
- **リンクの検査**：`parseOrderLink` が、`e`・`o` を英数字20文字に限る。20文字未満・超過・日本語などを、単体テストで確かめている
- **振動**：直前が調理中で、新しいのができあがり、のときだけ。最初の表示（`prev` が `null`）では、鳴らない
- **ビルドの検査**（`scripts/build.mjs`）：`customer.html` の `script` と `modulepreload` を数え、gzip後 200KB を超えるか、0個なら、ビルドを失敗させる。DESIGN.md の F1（約135KB）と合う
- **ルール**：未ログインの利用者が、本物のルールの下で、注文1件を読めること・一覧は拒否されることを、結合テストが確かめている
- **設計書**：DESIGN.md（F1）、data-access.md §3.6、screens.md §4.2・§4.3、testing.md の記述は、コードと矛盾しない
