# ADR-0002: Service Workerを導入し、ホーム画面への追加は任意にする

- 状態: 採用（Accepted）
- 日付: 2026-10-03

## 背景

- スタッフは、1台の端末を1日中使う。PayPayの入金確認などで他のアプリに切り替えると、iPhoneがSafariのタブを破棄することがある。会場の通信が途切れているときに再読み込みすると、画面が開けない
- 仕様では、通信がなくてもステータス変更ができる（SPEC 7.3）。画面が開けないと、これが成り立たない
- 一方、iPhoneのホーム画面に追加したアプリは、Safariとは保存領域が別で、Googleログインの動作（popup / redirect）や、ログインの保持に不確実性がある
- お客様には、インストールなどの手間をかけさせたくない

## 検討した選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| A | PWAなし（Service Workerもmanifestも使わない） | 実装は最小。ただし、再読み込み時にオフラインで開けない |
| **B** | **Service Workerを導入し、ホーム画面への追加は任意** | 実装は小さい。オフラインでも開ける。ログインは、通常のSafariで済む |
| C | ホーム画面への追加を必須にする | 全画面にできるが、iOSでのログインの検証結果に依存し、当日のリスクが高い |

## 決定

B案を採用する。

- Service Workerは、スタッフ用画面だけに入れる。お客様画面（`/s`）には入れない（インストールも、キャッシュの仕組みも使わない）
- manifestとアイコンは用意し、ホーム画面に追加できるようにするが、**任意**。追加を勧めるのは、実機でログインが確認できてから（U1）
- 開発中は入れない（キャッシュで、開発中の確認が混乱するため）。マイルストーン7で、独立した作業として導入する。導入しても、他のコードは変更しない
- Service Workerは、新しい版を裏で取得し、次の起動で切り替える。イベント当日の朝には、デプロイしない

## 結果

- 良い点: オフラインでも画面が開く。ログインの不確実性（iOSのホーム画面アプリ）が、必須要件から外れる
- 悪い点・リスク: 古い版が残る可能性がある（更新方式と、当日朝にデプロイしない運用で対処）。Safariのタブのまま使うと、しばらく開かないときに、ログインが消えることがある（当日の数日前にログイン状態を確認する）
- 実機の確認（#20、2026-10-08。dev の iPhone）：Service Worker 導入後、機内モードでスタッフ画面が起動する。`/s` は影響を受けない（機内モードでは通信エラー）。ホーム画面に追加したアプリで、Googleログインができた。**決定：ホーム画面への追加を勧めてよい**（任意のまま。必須にはしない）。機内モードの起動直後は、「読み込み中」が、しばらく出る（接続状態の判定は、通常どおり出る）
- 見直す条件: ホーム画面アプリでのログインが問題なく動くと確認できたら、追加を推奨してよい。Service Workerの更新で問題が頻発した場合は、案Aを再検討する
